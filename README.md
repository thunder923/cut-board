# CUT BOARD — 絵コンテアプリ

動画制作の絵コンテ（カット割り）をブラウザで作れる静的Webアプリです。カメラワーク標準48種類（[Motion Prompt](https://github.com/showheyohtaki/motion-prompt) の camera＋camera2 に準拠）を備え、カスタム演出を **アプリ内** と **コード** の両方から管理できます。

**公開URL: https://thunder923.github.io/cut-board/**

## 使い方

1. 公開URLを開く（ログインなしでもローカル保存で使えます）
2. プロジェクトを作り、カットを追加
3. 各カットにシーン／カット番号、尺（秒数）、演出メモを入力し、カメラワークを一覧から選ぶ
   - 一覧はカテゴリチップで絞り込み、名前・英語名・説明・タグで検索できます
   - プリセットを選ぶと説明と「使いどころ」が表示され、「AI用プロンプトをコピー」で動画生成AI等に貼れる指示文をコピーできます
4. 必要に応じて描画、参考画像の添付、3Dシーンでのカメラ位置確認
5. 共有・保存は「画像で共有（PNG）」「印刷 / PDF保存」、バックアップはJSON書き出しから

## カメラワーク48（Motion Prompt準拠）
標準プリセットは Motion Prompt（showheyohtaki/motion-prompt、MIT License (c) 2026 Shohei Ohtaki）の2パック全48種です。各プリセットには日本語名・英語名・説明・「使いどころ」と Motion Prompt 番号を持ち、アプリから動く見本（https://showheyohtaki.github.io/motion-prompt/#番号）へリンクします。

- 01-24 = camera #025-048（従来版と同一の割当。既存プロジェクトの番号はそのまま使えます）
  - カメラの動き: パン／ティルト／ドリーイン／ズームイン／トラッキング／オービット／クレーンアップ／ドリーズーム
  - 撮り方・時間: ラックフォーカス／手持ち風／FPV／ダッチアングル／スローモーション／スピードランプ／タイムラプス／フリーズフレーム
  - 切り替え: ジャンプカット／マッチカット／ホイップパン／クロスディゾルブ／ワイプ／スマッシュカット／Jカット／Lカット
- 25-48 = camera2 #169-192
  - カメラの動き: ペデスタル／バレルロール／ハイパーラプス／長回し／ステディカム／フォローショット／ロックオフ／フライスルー
  - アングル・画づくり: ローアングル／ハイアングル／POVショット／オーバーザショルダー／バーズアイ／ディープフォーカス／エスタブリッシングショット／エクストリームクローズアップ
  - 切り替え・編集: インサートショット／モーフカット／フェードアウト／アイリスアウト／カットアウェイ／クロスカッティング／バレットタイム／モンタージュ

PNG書き出しのカメラ表記にも英語名と Motion Prompt 番号が入ります。

## 現在の主な機能
- 標準48種類のカメラワーク（Motion Prompt camera＋camera2準拠、カテゴリ絞り込み・キーワード検索・動く見本リンク・AI用プロンプトコピー付き）
- アプリ内カスタム演出の追加
- `custom-cameras.js` によるコード管理の共通演出
- カット追加、複製、削除、上下移動
- 秒数、場面、演出メモ
- 指/マウス描画、参考画像の添付
- 画像/PDFの取り込み（画像は1カット、PDFは各ページを画像化してカット化）
- JSON書き出し/読み込み
- 印刷・PDF保存、カットごとのPNG書き出し

## カスタム演出を追加する方法

### A. アプリ内で追加（コード不要）
1. アプリ左側の「カスタム演出を追加」へ。
2. 名前、英語名、説明を入力して登録。
3. カットを選んで、カメラワーク欄から登録した演出を選ぶ。

この方法で追加した演出は「自分の演出リスト」に保存され、新しいプロジェクトでも再利用できます。リストは同じブラウザ内の `localStorage` に保存されます。プロジェクトを新規作成しても演出リストは残ります。JSONバックアップには個人用演出リストも含まれるため、別端末に移す場合は書き出したJSONを読み込んでください。

### B. GitHubのコードで追加（全利用者共通）
`custom-cameras.js` を編集し、配列に次のような項目を追加してコミットします。

```js
window.CUTBOARD_CUSTOM_CAMERAS = [
  {
    id: "G01",
    name: "スライダー移動",
    english: "Slider move",
    description: "スライダーで水平に移動する"
  }
];
```

- `id` は `G01`、`G02` のように重複しないIDにしてください。
- `name` は必須です。`english` と `description` は任意です。任意で `category`（`"move"|"style"|"angle"|"transition"`）、`mp`（Motion Prompt番号。見本リンクになります）、`usage`（使いどころ）、`tags`（検索用キーワード）も付けられます。
- GitHub上でファイルを編集してコミットすると、公開サイトにも反映されます。
- コードで追加した演出はサイト利用者全員に表示されます。個人のプロジェクトだけに保存したい場合はアプリ内追加を使ってください。

## 3Dシーンスタジオ

各カットの「♟ 3Dシーン」から実際の3D空間を開けます。大人／子供・男女の人物を複数配置し、役名を付けられます。椅子・ベンチ・木のほか、2 MiB以下のGLB形式モデルを追加できます。外部モデルはPoly PizzaやKenneyから検索し、配布元の利用条件を確認してダウンロード後に読み込みます。モデルデータもプロジェクトとJSONバックアップに含まれ、Google Driveにも保存されます。

撮影カメラは三脚／手持ちを切り替え、3Dギズモで位置と高さを調整できます。注視点も設定でき、レンズ焦点距離は35mm換算のmmで調整します。カメラ視点の画像をカットへ保存し、配置データはJSONバックアップにも含まれます。人物ポーズプリセットと関節調整も引き続き使えます。

3D描画はThree.jsのCDN読み込みを使います。人物と小道具は基本形状を組み合わせた軽量モデルなので、WebGL対応ブラウザとインターネット接続が必要です。外部モデル配布サービスや有料アセットは使用しません。

## 画像・PDFの取り込みと共有
- サイドバーから画像/PDFを選択すると、画像は1カット、PDFは各ページを画像化してカットとして追加します（PDF読み込みはPDF.js CDNへの接続が必要です）。
- 作品名・制作日/受領日・各カットのシーン名で整理できます。
- 「印刷 / PDF保存」からブラウザの印刷画面でPDF保存できます。
- 「画像で共有（PNG）」はカットごとのPNGを書き出します。iPhoneでは複数ダウンロードの許可を求められる場合があります。

## データの扱い（保存・ログイン・同期）
プロジェクトは引き続きブラウザの `localStorage` に保存されます。ログイン後に「Google Driveを接続」を選ぶと、Google Driveのアプリ専用 `appDataFolder` を保存先として許可できます。メール／パスワードで登録した人も、自分のGoogleアカウントを追加接続できます。ローカルデータは自動で移行されません。「このローカルプロジェクトをDriveに新規保存」を選ぶと新しいファイルを作り、その後の編集を同期します。既存データを読み込む場合は確認を表示します。複数端末での同時更新は、Driveの更新情報を使って可能な範囲で検出し、競合時は自動上書きを止めます。

Drive上のデータは各利用者のGoogleアカウントに紐づき、各利用者のDrive容量を使います。`appDataFolder` はDriveの通常画面には表示されないため、重要な作品はアプリのJSON書き出しでもバックアップしてください。Drive APIにはアプリ側の利用上限もあります。Firebase Sparkプランの課金設定は不要です。

メールアドレスで新規登録すると、Firebaseから確認メールが送信されます。リンクを開いて確認が完了するまで、メール／パスワードアカウントのクラウド機能は使えません。設定画面から確認メールの再送と確認状態の更新ができます。ログイン画面の「パスワードを再設定」から再設定メールも送信できます。送信メールの件名や本文はFirebase ConsoleのAuthentication → Templatesで編集できます。

### 運用者向けセットアップ（Firebase / Drive連携を使う場合）
利用開始前にFirebase AuthenticationでGoogleとメールアドレス／パスワードを有効にし、承認済みドメインに `thunder923.github.io` を追加してください。Google Cloud ConsoleではGoogle Drive APIを有効にし、OAuth同意画面を設定します。Google Auth Platformの「クライアント」にあるWebクライアントには、承認済みJavaScript生成元として `https://thunder923.github.io` を登録してください。アプリが求める権限は `https://www.googleapis.com/auth/drive.appdata` で、各利用者のCUT BOARD専用の非表示領域だけにアクセスします。Firebase Authenticationはログインとアカウント識別に使用しますが、プロジェクト本文はFirestoreやFirebase Storageには保存しません。Firestoreルールの変更も不要です。

## プライバシーポリシー

- プロジェクトはブラウザの `localStorage` に保存され、作者のサーバーへ送信されることはありません
- Google Drive同期を使う場合に限り、プロジェクトは利用者自身の Google Drive のアプリ専用領域（`appDataFolder`）に保存されます。アプリが求める権限は `drive.appdata` のみで、Drive上のデータは各利用者のGoogleアカウントに属します
- Firebase Authentication はログインとアカウント識別だけに使います。プロジェクト本文を Firestore や Firebase Storage に保存することはありません（旧版で Firestore に保存したデータがある場合のみ、読み取り専用の移行機能があります。元データは削除されません）
- ライブラリ（Firebase / PDF.js / Three.js など）はCDNから読み込むため、ページ表示時に各配信元へ通常のWebアクセスが発生します
- JSONの書き出し・読み込みは端末内で完結します

## GitHub Pagesで公開する（フォーク・再デプロイ用）

1. GitHubで新しいリポジトリを作成（例：`cut-board`）。
2. このフォルダの中身をリポジトリのルートへアップロードします（ZIPファイルそのものではなく、展開した中身）。
3. リポジトリの **Settings → Pages** を開きます。
4. **Build and deployment → Source** で **Deploy from a branch** を選択。
5. Branch を `main`、フォルダを `/(root)` にして **Save**。
6. Pages画面に表示されるURLを開きます。公開反映まで少し時間がかかることがあります。

GitHub公式ガイド: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
